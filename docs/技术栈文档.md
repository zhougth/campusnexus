## 1. 选型原则

1. **单体优先**：校园项目先做一个可部署的 Spring Boot 单体，不引入微服务、注册中心、消息队列等额外复杂度。
2. **本地可跑**：MySQL、Redis、Chroma、MinIO 全部可用 Docker Compose 启动，开发者不依赖云资源也能完成主流程。
3. **可替换**：LLM、Embedding、OSS 都通过配置切换供应商，不把某一家云服务写死在业务代码里。
4. **中文校园场景优先**：Embedding 选中文效果稳定的模型，文档解析覆盖 PDF/Word/Excel/PPT/HTML/CSV。
5. **成本可控**：LLM 调用加超时、重试、限流；向量化手动触发且异步执行，避免上传接口长时间阻塞。
6. **契约先行**：接口文档、数据库文档、框架文档先于代码，代码以文档为验收依据。

## 3. 关键选型决策

### 3.1 Spring MVC + SseEmitter，而不是 WebFlux

- 项目的数据访问是 MyBatis-Plus + JDBC，阻塞模型；引入 WebFlux 会造成“阻塞 JDBC 跑在事件循环”的反模式。
- SSE 只需要单向流式输出，`SseEmitter` 足够；LLM 的流式回调通过线程池桥接到 emitter。
- 若后续全站改为 R2DBC，再评估 WebFlux；当前不做。

### 3.2 MyBatis-Plus + Flyway，而不是 JPA

- 业务以列表查询、条件筛选、分页为主，MyBatis-Plus 的条件构造器和分页插件更直接。
- 复杂统计（仪表盘、提问日志）用 XML/自定义 SQL 更可控。
- Flyway 管理 DDL 与种子数据，保证开发/测试/生产库结构一致。

### 3.3 MySQL 8 + Redis 7，不上 Elasticsearch

- MVP 的知识量在万级以内，公共搜索使用 MySQL `LIKE`，RAG 使用 Chroma 向量检索。
- MySQL `LIKE '%关键词%'` 无法使用普通索引，但万级数据可接受；数据量上来后再加 MySQL ngram 全文索引。
- Elasticsearch 会显著增加部署与运维成本，本期不引入。

### 3.4 Chroma 作为向量库，而不是 pgvector

- Chroma 单容器即可运行，metadata 过滤和 collection 管理简单，适合课程/校园项目。
- 若未来要求与业务库同事务或大规模过滤，再评估 pgvector/Milvus。
- Chroma 不是唯一事实源：知识正文以 MySQL 为准，Chroma 只存分片与向量。

### 3.5 手动异步向量化

- 上传/导入/审核通过只写 MySQL，并把 `vectorStatus` 置 0，不阻塞用户请求。
- 管理员点击“同步向量”后创建异步任务，后台线程池分批处理 `status=1 AND vectorStatus IN (0,2)` 的知识。
- 任务记录落 `async_task` 表，进度通过统一任务接口查询；批次回滚与向量化共用线程池和任务模型。
- 检索层只使用 `vectorStatus=1` 的知识，避免旧向量/未同步内容污染回答。

### 3.6 会话、批次、任务使用 UUID

- 会话对外 `sessionId` 使用 UUID，避免自增 ID 被枚举导致历史会话泄露。
- 导入批次 `batchId`、异步任务 `taskId` 同样使用 UUID。
- 业务主键仍使用数据库自增 BIGINT，便于索引与关联。

### 3.7 JWT + Redis 黑名单 + tokenVersion

- JWT 无状态，登出后必须用 Redis 黑名单让当前 Token 立即失效。
- 修改密码、禁用用户、修改角色使用 `tokenVersion + 1`，让该用户全部 Token 失效。
- Redis 故障策略：管理端接口 fail-closed；普通读接口可按部署要求选择 fail-open。

### 3.8 动态分类

- 分类由 `knowledge_category` 表维护，管理员可新增/改名/排序/停用。
- 公共端通过 `GET /api/common/categories` 获取启用分类；前端不再硬编码 1-10。
- 分类被知识或贡献引用时禁止删除，只能停用。

### 3.9 混合检索

- 公共知识库搜索只查 MySQL（关键词/分类/分页）。
- 智能问答的 FAQ 意图使用 **Chroma 向量 + MySQL 关键词** 两路召回，按 `knowledgeId` 合并去重后再交给 LLM。
- 关键词分支用 MySQL `LIKE`；后续可替换为 ngram 全文索引，不改变上层接口。

### 3.10 文件存储

- 生产使用阿里云 OSS；本地开发使用 MinIO，接口层只依赖 `FileStorageService`。
- 知识文档上限 20MB，头像上限 5MB；上传做扩展名 + MIME + 文件头校验。
- OSS 路径按日期和 UUID 分目录，数据库保存 URL 与原始文件名。

## 8. 非目标

本期明确不做：

- 爬虫/网页采集；
- 微服务拆分、注册中心、消息队列；
- Elasticsearch；
- 多租户；
- 复杂 RBAC（仅普通用户/管理员两种角色）；
- Refresh Token（Token 过期重新登录）；
- 分布式向量库集群；
- 跨库强一致事务（MySQL 与 Chroma 采用状态机 + 重试）。

## 9. 主要风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 延迟/费用 | 问答慢、成本高 | 超时、重试、限流；默认关闭长上下文；记录 token 用量 |
| Chroma 与 MySQL 不一致 | 旧内容被检索 | `vectorStatus` 过滤 + 异步任务 + 删除/回滚重试 |
| MySQL `LIKE` 性能 | 大数据量搜索慢 | MVP 控制数据量；后续 ngram 全文索引/ES |
| SSE 被代理缓冲 | 前端看不到逐字输出 | Nginx `proxy_buffering off`、`X-Accel-Buffering: no` |
| 上传文件解析失败 | 导入中断 | Tika + 大小/格式校验 + 明确错误码 20005-20009 |
| Redis 故障 | 登出黑名单失效 | 管理端 fail-closed；监控与告警 |
| 手动向量化遗漏 | 新知识搜不到 | 管理端显示待同步数量；任务列表与提醒 |
| 分类被误删 | 知识失去分类 | 引用检查 + 停用代替删除 |

## 10. 版本与升级策略

- 所有依赖在项目初始化时锁定版本，禁止 `LATEST`。
- 升级遵循：开发环境验证 → 集成测试 → 预发 → 生产。
- Spring Boot 小版本升级需回归：Security、Jackson、MyBatis-Plus、LangChain4j。
- Chroma/Embedding 模型升级必须重建 collection，并记录 embedding 模型与维度。
