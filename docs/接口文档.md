## 1. 通用说明

### 1.1 统一返回格式

除 SSE 流式接口外，所有接口返回统一 JSON 结构：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1715875200000
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 状态码，200 表示成功 |
| `message` | string | 提示信息 |
| `data` | any | 响应数据，具体结构见各接口 |
| `timestamp` | long | 响应时间戳（毫秒） |

### 1.2 错误响应与状态码

除 SSE 外，错误响应与成功响应同构：

```json
{
  "code": 10001,
  "message": "用户名已存在",
  "data": null,
  "timestamp": 1715875200000
}
```

**判定规则**

- `code = 200` 表示成功；前端以 `body.code === 200` 判断成功，不能依赖 `message`。
- HTTP 状态码表达协议/鉴权层结果；业务规则错误统一返回 HTTP 200，`code` 使用 10001 起的业务码。
- 422 仅用于 `@Valid` 请求体校验失败；400 用于 JSON 解析失败、缺少必填 query/path 参数、枚举值非法。
- 所有需鉴权接口均可能返回 401/403；所有接口均可能返回 500；下文各接口仅列业务错误，不再重复。
- SSE 接口的错误通过 `error` 事件返回：`{"type":"error","code":30001,"content":"AI 服务调用失败"}`。

**协议层状态码**

| HTTP / code | 说明 |
|--------|------|
| 200 | 成功，或业务错误（以 `code` 区分） |
| 202 | 已接受，异步任务已创建 |
| 400 | 请求格式错误 |
| 401 | 未认证（`code` 可为 10004 / 10005） |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 405 | 请求方法不允许 |
| 422 | 参数校验失败，`data` 为字段错误映射 |
| 429 | 请求过于频繁 |
| 500 | 服务器内部错误 |
| 503 | 依赖服务不可用 |

**业务状态码**

| code | 说明 |
|--------|------|
| 10001 | 用户名已存在 |
| 10002 | 用户不存在 |
| 10003 | 密码错误 |
| 10004 | Token 已过期 |
| 10005 | Token 无效 |
| 10006 | 账号已禁用 |
| 10007 | 邮箱已存在 |
| 20001 | 知识条目不存在 |
| 20002 | 分类不存在或已停用 |
| 20003 | 贡献条目不存在 |
| 20004 | 该贡献已被审核，不可重复操作 |
| 20005 | 上传文件过大（具体上限见接口） |
| 20006 | 不支持的文件格式 |
| 20007 | 文档解析失败 |
| 20008 | 文件上传 OSS 失败 |
| 20009 | LLM 文档切分失败 |
| 20010 | 该反馈已提交，请勿重复操作 |
| 20011 | 该反馈已处理，不可重复操作 |
| 20012 | 分类正在使用，无法删除 |
| 20013 | 已有向量类异步任务正在执行 |
| 20014 | 该导入批次已回滚 |
| 20015 | 批次内存在上传后修改的知识，需 `force=true` |
| 20016 | 不能对当前登录管理员执行该操作 |
| 20017 | 系统至少保留一个管理员 |
| 30001 | AI 服务调用失败 |
| 30002 | AI 服务响应超时 |

**422 错误示例**

```json
{
  "code": 422,
  "message": "参数校验失败",
  "data": { "username": "长度必须在 3-20 之间" },
  "timestamp": 1715875200000
}
```

### 1.3 鉴权说明

鉴权方式：请求头携带 `Authorization: Bearer <token>`。JWT 过滤器解析成功后，会将 `userId` 写入 `RequestAttribute`，Controller 无需前端显式传参。Token 有效期 24 小时，过期后需重新登录，不提供 refresh 接口。

| 路径 | 是否需要 Token | 角色要求 |
|------|:---:|------|
| `POST /api/auth/register`、`POST /api/auth/login` | 否 | 无 |
| `POST /api/auth/logout` | 是 | 登录用户 |
| `GET /api/auth/me` | 是 | 登录用户 |
| `PUT /api/auth/profile`、`/api/auth/password`、`/api/auth/avatar` | 是 | 登录用户 |
| `GET /api/chat/stream`、`POST /api/chat/session` | 否 | 无（携带 Token 时会话绑定用户） |
| `GET /api/chat/sessions`、`GET /api/chat/history` | 是 | 登录用户 |
| `/api/common/**` | 否 | 无 |
| `/api/contribute/**` | 是 | 登录用户 |
| `POST /api/feedback/submit` | 是 | 登录用户 |
| `/api/feedback/admin/**` | 是 | 管理员（ROLE_ADMIN） |
| `/api/admin/**` | 是 | 管理员（ROLE_ADMIN） |

> 说明：`ROLE_ADMIN` 对应用户 `role = 1`；管理员同时拥有 `ROLE_ADMIN` 与 `ROLE_USER` 权限。
> 主动登出后当前 Token 立即失效；修改密码或被禁用后，该用户全部 Token 立即失效。

### 1.4 分类初始数据（动态维护）

| categoryId | 名称 |
|:---:|------|
| 1 | 食堂餐饮 |
| 2 | 图书馆 |
| 3 | 教务教学 |
| 4 | 宿舍生活 |
| 5 | 校园交通 |
| 6 | 社团活动 |
| 7 | 就业创业 |
| 8 | 校园卡务 |
| 9 | 医疗健康 |
| 10 | 其他 |

> 上表仅为本期初始化种子数据。分类由管理员通过 7.13 维护，公共端通过 4.7 获取；`categoryId` 以数据库为准，不再限定 1-10。返回的 `categoryName` 必须与数据库中的分类名称一致。

### 1.5 分页约定

- `page` 从 1 开始；`size` 默认 10，最大 100，超过上限按 100 处理。
- 所有 `page/size` 分页接口统一返回 `PageResultVO`：`{ total, page, size, records }`。
- 游标分页（3.4 会话历史）使用 `limit` + `beforeMessageIndex`，返回消息数组，不使用 `PageResultVO`。
- 默认排序：知识与贡献按 `createTime desc`，反馈按 `createTime desc`，历史消息按 `messageIndex asc`。

### 1.6 数据约定

- 时间格式统一为 `yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai`。
- 主键使用数据库自增 `BIGINT`（MyBatis-Plus `IdType.AUTO`），API 中以 number 返回，不使用雪花 ID；若未来切换雪花 ID，必须序列化为字符串。
- 会话对外标识使用 UUID 字符串，不可枚举。
- 除上传/SSE 外，请求与响应均为 `application/json;charset=UTF-8`；上传为 `multipart/form-data`；SSE 为 `text/event-stream`。
- `message` 仅用于展示，前端判断成功必须以 `code` 为准。

## 3. 智能问答 — `/api/chat`

> **核心业务**：基于 RAG（混合检索 + 多 Agent 编排）的流式智能问答，支持会话管理与回答缓存。
> `GET /api/chat/stream`、`POST /api/chat/session` 为公开接口；`/api/chat/sessions`、`/api/chat/history` 需登录且只能访问自己的会话。
> 会话对外标识使用 UUID，不可枚举；匿名用户可凭 UUID 继续会话，但无法查看历史列表。

### 3.1 流式聊天（SSE）

```
GET /api/chat/stream?question={question}&sessionId={sessionId}
```

- **Content-Type：** `text/event-stream`
- **连接方式：** 服务端以默认 `message` 事件推送，`data` 为 JSON；客户端按 `type` 字段分发，不要监听 `status` / `token` 事件名。
- **鉴权：** 原生 `EventSource` 不支持自定义请求头。需要绑定用户会话时，前端使用 `fetch` + `ReadableStream` 携带 `Authorization`；未携带 Token 也可连接，此时创建匿名会话。
- **返回类型：** 由服务端实现决定（Spring MVC `SseEmitter` 或 WebFlux `Flux<ServerSentEvent>`），对外契约统一为 `text/event-stream`。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `question` | string | 是 | 用户问题，URL 编码，最大 500 字符 |
| `sessionId` | string | 否 | 会话 UUID；不传则自动创建；不存在返回 404；会话已绑定用户且请求者不是本人时返回 403 |

**处理流程：**

```mermaid
graph LR
    A[用户提问] --> B{问题长度 > 50}
    B -->|是| C[QueryDecompositionAgent 分解子问题 → 并行检索 → 合并去重]
    B -->|否| D[QueryRewritingAgent 改写 + 意图分类]
    D --> E{意图}
    E -->|FAQ| F[多轮检索 → 上下文]
    E -->|ACCOUNT/COURSE| G[桩数据]
    E -->|CHITCHAT| H[跳过 RAG]
    C --> I[ContextCompressionAgent 压缩(>1200字)]
    F --> I
    I --> J[AgentRouter 路由 → LLM 流式生成]
    J --> K[SSE 逐字推送]
    K --> L[记录提问日志 + 推荐 + 追问引导]
```

> FAQ 意图的检索采用混合检索：**Chroma 向量检索 + MySQL 关键词检索**，按 `knowledgeId` 合并去重后再交给 LLM。向量检索仅使用 `status=1` 且 `vectorStatus=1` 的知识；尚未同步向量的知识仍可能被 MySQL 关键词分支命中。`done.matchCount` 为合并去重后的知识条数。

**SSE 事件类型：**

| 事件类型 | 格式 | 说明 |
|----------|------|------|
| `status` | `{"type":"status","content":"正在搜索相关知识..."}` | 处理阶段通知 |
| `token` | `{"type":"token","content":"食"}` | 逐字输出 |
| `done` | 见下方 | 终止事件，回答结束 |
| `followUp` | `{"type":"followUp","content":"你可能还想了解..."}` | 追问引导（可选，在 `done` 之前） |
| `error` | `{"type":"error","code":30001,"content":"AI 服务调用失败"}` | 终止事件 |

**`done` 事件字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `sessionId` | string | 会话 UUID |
| `confidence` | string | 可信度：`high`（≥2 条匹配）/ `medium`（1 条）/ `low`（无匹配） |
| `source` | string | 答案来源：`rag_knowledge_base`（知识库）/ `ai_generated`（AI 生成） |
| `matchCount` | int | 知识库检索命中条数 |
| `logId` | long | 提问日志 ID，始终返回；提交反馈时回传 |
| `recommendations` | array | 个性化推荐列表（可选），元素为 `{knowledgeId, title, reason}` |

**流结束规则：**

- `done` 或 `error` 为终止事件，服务端随后关闭连接；`error` 之后不会再发 `done`。
- 服务端每 15 秒发送注释行 `: keep-alive`；客户端断开后服务端停止生成。
- 未登录时也会生成提问日志（`userId` 为空），但匿名日志不支持提交反馈。
- 部署时需关闭反向代理缓冲（如 Nginx `X-Accel-Buffering: no`），否则 token 可能被攒包。

**响应示例（SSE 流）：**

```
data: {"type":"status","content":"正在搜索相关知识..."}

data: {"type":"status","content":"找到2条相关资料，正在生成回答..."}

data: {"type":"token","content":"食"}

data: {"type":"token","content":"堂"}

data: {"type":"followUp","content":"你可能还想了解：图书馆开放时间"}

data: {"type":"done","sessionId":"5f0c7a9e-3b2d-4c8a-9e1f-7d6b2a4c8e10","confidence":"high","source":"rag_knowledge_base","matchCount":2,"logId":456,"recommendations":[{"knowledgeId":25,"title":"校车时刻表","reason":"同分类热门"}]}
```

**可能的错误：** `401` 携带的 Token 无效 / `404` 会话不存在 / `403` 会话不属于当前用户 / `429` 请求过于频繁 / `error` 事件携带 `30001`、`30002`

> 会话校验与限流在建立 SSE 流之前返回对应 HTTP 状态码；流建立后的错误通过 `error` 事件返回。
> 聊天默认每用户/每 IP 每分钟 10 次（匿名按 IP），超限返回 HTTP 429，不建立 SSE 流；具体阈值可配置。

## 6. 知识反馈 — `/api/feedback`

> 收集用户对 AI 回答的满意度反馈（点赞 / 点踩 / 举报），与聊天 `done` 事件中的 `logId` 形成闭环。
> 仅允许对当前登录用户自己的提问日志提交反馈；匿名提问日志不支持反馈。
> `dislike` 且携带纠错内容时，会自动创建一条 `correction` 贡献（进入众包审核流程）。
> `/api/feedback/admin/**` 仅管理员（ROLE_ADMIN）可访问。

### 6.1 提交反馈

```
POST /api/feedback/submit
```

**请求头：** `Authorization: Bearer <token>`

**请求体（FeedbackSubmitDTO）：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `logId` | long | 是 | 提问日志 ID（取自 SSE `done` 事件的 `logId`），必须属于当前登录用户 |
| `feedbackType` | string | 是 | 反馈类型：`like` / `dislike` / `report` |
| `knowledgeId` | long | 否 | 关联知识条目 ID |
| `sessionId` | string | 否 | 关联会话 UUID |
| `content` | string | 否 | 反馈文字内容，最长 1000 |
| `correctAnswer` | string | 否 | 用户提交的正确答案，最长 2000；仅 `dislike` 时有效 |

**请求示例：**

```json
{
  "logId": 456,
  "feedbackType": "dislike",
  "knowledgeId": 12,
  "correctAnswer": "食堂晚上 21:30 关门，不是 22:00。"
}
```

```json
{
  "code": 200,
  "message": "反馈提交成功",
  "timestamp": 1715875200000,
  "data": "反馈提交成功"
}
```

> 同一用户对同一 `logId` 的同一 `feedbackType` 只能提交一次，重复提交返回 `20010`。
> `dislike` + `correctAnswer` 时自动创建的贡献：`type=correction`、`status=0`、`categoryId` 取关联知识的分类（无则为 10）、`remark` 标记“来自点踩反馈”，并会出现在 5.2 我的贡献列表。
> `sessionId` 填写时必须与 `logId` 所属会话一致。

**可能的错误：** `401` 未授权 / `403` 日志不属于当前用户 / `404` 提问日志不存在 / `422` 参数校验失败（logId、feedbackType 不能为空） / `20010` 该反馈已提交

### 7.4 上传文档入库

```
POST /api/admin/knowledge/upload
```

> 上传 PDF/Word/Excel/PPT/TXT/Markdown/HTML/CSV 文档，自动进行 LLM 语义切分、关键词与问法变体生成后入库。
> 本接口为异步：文件落库后立即返回 `202` 和 `batchId`，解析、LLM 生成与知识写入在后台线程执行；前台应轮询 7.15 批次详情，直到 `status` 变为 `SUCCESS` 或 `FAILED`。

**Content-Type：** `multipart/form-data`

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `file` | file | 是 | 文档文件（≤ 20MB） |
| `categoryId` | long | 是 | 目标分类 ID（见 4.7，且必须为启用状态） |
| `keywords` | string | 否 | 补充关键词，逗号分隔，最长 500 |

**支持的文件类型：** `pdf` / `doc` / `docx` / `xls` / `xlsx` / `ppt` / `pptx` / `txt` / `md` / `markdown` / `html` / `htm` / `csv`

**curl 示例：**

```bash
curl -X POST "http://localhost:8080/api/admin/knowledge/upload" \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -F "file=@/path/to/handbook.pdf" \
  -F "categoryId=1" \
  -F "keywords=手册,新生,指南"
```

**响应示例（data 为 DocumentUploadResponse）：**

```json
{
  "code": 202,
  "message": "任务已提交",
  "timestamp": 1715875200000,
  "data": {
    "batchId": "b8f3c2a1-6d4e-4a7b-9c1d-2e5f8a0b7c34",
    "originalFilename": "handbook.pdf",
    "fileType": "pdf",
    "fileUrl": "https://campusnexus.oss-cn-beijing.aliyuncs.com/2026/06/xxx.pdf",
    "docTitle": null,
    "knowledgeCount": 0,
    "totalChars": 0,
    "status": "PROCESSING"
  }
}
```

> 每次上传都会创建一个导入批次（`batchId`），批次列表/详情见 7.15。异步处理完成前 `knowledgeCount/totalChars` 为 0，最终值以批次详情为准。本批次生成的知识 `vectorStatus` 均为 0，需调用 7.10 同步向量后才会进入向量检索。

**可能的错误：** `20002` 分类不存在或已停用 / `20005` 文件过大 / `20006` 格式不支持 / `20008` 上传 OSS 失败

> `20007` 解析失败、`20009` 切分失败发生在后台处理阶段，不会从上传接口返回；通过 7.15 批次详情查看 `status=FAILED` 和 `errorMessage`。

```
GET /api/admin/import-batches/{batchId}
```

**响应示例（data 为 ImportBatchDetailVO）：** 在 ImportBatchVO 基础上增加 `vectorSyncedCount`、`vectorPendingCount`、`vectorFailedCount`；批次内知识列表使用 7.2 的 `importBatchId` 筛选。

**可能的错误：** `404` 导入批次不存在

---

### 7.16 批次回滚（可选，异步）

> 本期可先只做 7.15 的回溯；若实现回滚，按以下契约执行。回滚是破坏性操作，前端必须二次确认。

```
POST /api/admin/import-batches/{batchId}/rollback
```

**请求体（BatchRollbackDTO）：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:---:|:---:|------|
| `force` | boolean | 否 | false | 批次内存在上传后被修改的知识时，必须为 true 才继续 |
| `deleteFile` | boolean | 否 | false | 是否同时删除 OSS 原始文件 |

**响应示例（HTTP 202）：**

```json
{
  "code": 202,
  "message": "回滚任务已创建",
  "timestamp": 1715875200000,
  "data": {
    "taskId": "c2d4e6f8-0a1b-4c3d-9e5f-7a8b9c0d1e2f",
    "status": "PENDING"
  }
}
```

> 回滚任务会：逻辑删除该批次创建的 MySQL 知识、删除对应 Chroma 向量；`deleteFile=true` 时同时删除 OSS 原始文件。不会影响其他批次。任务进度通过 7.11 查询，`taskType=BATCH_ROLLBACK`。
> 是否“上传后被修改”以 `knowledge.updateTime` 晚于批次 `createTime` 判断。若存在且 `force=false`，返回 `20015`；已回滚的批次返回 `20014`；已有向量类任务运行返回 `20013`。

**可能的错误：** `404` 导入批次不存在 / `20013` 已有向量类异步任务正在执行 / `20014` 该导入批次已回滚 / `20015` 批次内存在上传后修改的知识，需 `force=true`
